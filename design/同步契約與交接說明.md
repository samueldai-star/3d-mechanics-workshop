## 2. 唯一的四個接點

### 接點 A — 場景定義 `AREAS`

四個場景共用一個 three.js scene，各自一個世界 X 偏移（`ox`）：

| id | 名稱 | ox | 面板主題 | 備註 |
|---|---|---|---|---|
| `workshop` | 力學工坊 | 0 | `warm` | 九角落、魔法陣、三出入口 |
| `range` | 拋射訓練場 | 200 | `warm` | 黃昆天空、砲台、標尺步道、箭靶 |
| `corridor` | 中央走廊 | 400 | `cool` | 能量水晶壁、能量河流、展示龕 |
| `tower` | 天文塔 | 600 | `night` | 星空圓頂、渾天儀、星軌橢圓環 |

每筆含 `bg / fogC / fogD`（環境色）、`home`（預設鏡位，坐標相對 `ox`）、`clamp`（漫步邊界）、`theme`。
`applyArea(id)` 負責切換：背景色、霧、各場景 group 顯示、鏡位、面板主題、hotspot 過濾。

### 接點 B — 角落定義 `CORNERS`

每筆新增 `area` 欄位（屬於哪個場景），`pos` 已含 `ox`：

位於 logic class 最上方，每個角落一筆：

```js
{
  id: 'turntable',            // 穩定 key，repo 端以此對應模擬器模組
  title: '旋轉圓盤平台',
  sym: 'τ = rF sinθ',
  color: '#4fc3ff',          // 該角落主題工作燈顏色（總覽視角的視覺錨點）
  pos: [5.0, 1.6, 8.8],      // 3D 世界座標，hotspot 掛點
  mark: '力矩與剛體',         // hotspot 上的副標
  formula: 'τ = r F sin θ',   // 面板下方大字公式
  wm: 'τ=Iα',                // 面板背景浮水印
  tabs: ['角動量守恆／半徑改變', '力矩方向 3D 右手定則', …],  // 面板上方分頁列
  readouts: [{ k: 'τ', v: '—— N·m' }, …]                    // 右欄即時數據
}
```

九個工坊角落（`area:'workshop'`）：`pulley` 繩索滑輪吊架、`anvil` 鐵匠砧台、`ramp` 木製斜坡、`sandpit` 碰撞沙坑試驗台、`turntable` 旋轉圓盤平台、`elevator` 電梯升降間、`drafting` 製圖桌、`tower` 高塔垂直落體井、`crystal` 發光水晶展示座。

新增九個場景角落：
- `range`：`catapult` 攻城砲台（拋射）、`ruler` 向量標尺步道（向量加減分解）、`targets` 箭靶落點區（平面運動描述）
- `corridor`：`chain` 能量轉換鏈節點、`heat` 熱功當量台、`entropy` 有序／無序展示龕
- `tower`：`kepler` 渾天儀軌道台、`cannon` 牛頓大砲、`telescope` 黃銅望遠鏡

新增角落 = repo 加一筆（含 `area`）+ 一個模擬器模組；場景端不需改動。

### 接點 C — 出入口定義 `EXITS` 與轉場

每筆：`{ id, area, to, kind, title, dest, color, pos }`。`kind` 決定轉場動畫：

| kind | 路線 | 轉場 |
|---|---|---|
| `door` | 工坊 → 拋射訓練場 | 鍵頭貼近、雙扇木門由中央向兩側推開（`_doorOpen`）、門縫暖光擴大、穿越門框後木紋暖色淡出（約 2.5s） |
| `arch` | 工坊 → 中央走廊 | 符文由外圈向内圈依序點亮（`_runeWake`）、中央浮現能量薄膜、穿越時光屏閃爍與色散 |
| `stair` | 工坊 → 天文塔 | `spiralUp()` 鍵頭沿螺旋路徑盤旋上升、暖黃提燈轉為清冷星光（約 3.2s） |
| `back` | 各場景 → 工坊 | 短淡出（約 1s） |

另有地圖面板上方四顆場景芯片（`jump(id)`）供考演時直接跳場，不跑儀式動畫。

### 接點 D — 面板中央模擬槽（每個分頁一個模擬器）

面板結構固定：標題列 / 分頁列 / 中央模擬槽 / 下方公式列 / 右側數據欄。
中央 `SIMULATION SLOT` 是掛載點，key 為 `${corner.id}:${tabIndex}`。

**場景端已提供全域註冊表（已實作，直接用）**：

```js
// repo 端模擬器只需註冊一個工廠函式，不需碰場景程式
WorkshopSimulators.register('turntable:1', () => ({
  mount(el){ /* el 是模擬槽，已清空且填滿容器 */ },
  unmount(){ /* 釋放 rAF / 監聽器 */ },
  onReadouts(cb){ /* cb([{k:'τ', v:'12.4 N·m'}, …]) 可以 60fps 呼叫 */ },
  reset(){}
}));
```

- 行為：開啟角落／切換分頁 → 自動 `unmount()` 舊的、`mount()` 新的；未註冊的 key 顯示「等待 repo 模擬器 · <key>」占位。
- 註冊時間不拘：面板已開啓後才 `register()` 也會立即掛上。
- `onReadouts` 的值直接寫入右欄 DOM（不走 React state），所以高頻更新不會導致模擬器被重新掛載；筆數以 `CORNERS.readouts` 的列數為上限。
- LIVE DATA 旁的小點：綠色 = 已掛載真正的模擬器，棕色 = 仍為占位。

```ts
interface Simulator {
  mount(el: HTMLElement): void;
  unmount(): void;
  onReadouts?(cb: (r: {k: string; v: string}[]) => void): void;
  reset?(): void;
}
```

模擬器不得改動面板底色、標題列、公式列。

## 3. 視覺規範（設計端負責，repo 端請勿改）

**總覽模式（暗）**
- 背景 `#0e0906`、指數霧、石造地基＋木地板拼接。
- 主光：天窗冷白光柱 `#dce9ff`（唯一投射陰影的主光）＋鍛爐橘光 `#ff7a24`＋五盞煉金提燈 `#ffab4d`。
- 每個角落一盞**主題色工作燈**（見 `CORNERS.color`），靠近時亮度由 9 → 15、hotspot 浮現同色暈光邊框。
- 科技感疊加：屋樑縫隙霓虹藍細線 `#4bb8ff`（呼吸明滅）、地面與長桌面工程網格＋力學符號浮水印（加法混合、緩慢呼吸）、符文拱門冷藍光。
- 塵埃粒子 520 點，低透明度。

**操作面板模式（亮）— 三套主題，依場景自動切換（`THEMES`）**
- `warm`（工坊、訓練場）：暖木漸層 `#f4e6cd → #e7d0aa`、黃銅標題列。
- `cool`（中央走廊）：白底配科技藍 `#f3f9fd → #d6e4f0`、藍灣標題列，強調抽象概念。
- `night`（天文塔）：清冷星空藍白 `#eff2fa → #d2daee`、靖藍標題列。
- 三套都必須保持亮底（者師在旁白板板書）；面板內僅低對比科技細節：淡藍網格、直角切邊、等寬字體數值、齒輪造型「回到工坊」按鈕。
- 文字色、列底色、數據列背景統一由 `paintUi()` 依 `data-p-*` 標記套用，repo 端模擬器請勿自行覆寫。
- 文字主色 `#2f1d0c`；公式列 ≥30px、數值 ≥23px（投影可讀性）。

**字體**：`Noto Serif TC`（標題／公式）、`Noto Sans TC`（介面）、`IBM Plex Mono`（符號與數值）。

### 2026-08-27（repo 端修正：角落面板展開順序，尚未回帶 Design 端）
- **repo 端直接修改**了 `mechanics-workshop.dc.html`（未經 Claude Design 畫布），請設計端下次編輯前先比對此變更，避免被舊版覆蓋。
- 面板開啟改為兩階段：
  1. `openCorner()` 等 `focusCorner()` 的 720ms 鏡頭轉場**完全結束**後才 `setState({ panel, tab:0, panelPhase:'shell' })`——只顯示標題列（殼），分頁列與預覽區维持 `opacity:0`。
  2. 殼的進場動畫穩定 300ms 後才 `setState({ panelPhase:'expanded' })`，分頁列與預覽區才淡入（新增 `panelExpand` keyframe，.26s）。
- 新增 `state.panelPhase`（`'shell'|'expanded'`）與方法 `paintPanelPhase()`；新增 refs `tabsBar`/`panelBody`（模板中對應 `tabsBarRef`/`panelBodyRef`）。
- **關鍵：`slotRef`／`slotHintRef` 沒有被包進條件渲染**——分頁列與預覽區是用既有 DOM＋`opacity`/`pointerEvents` 切換可見度，不是用 `sc-if` 整段掛載/卸載。這是刻意的：`slotRef` 一旦被 `sc-if` 卸載重掛，`syncSim()` 依 `panel`/`tab` 變化觸發掛載時 `this.slot.current` 會是 null，模擬器永遠不會真的 mount。改用 opacity 也讓模擬器能在殼顯示期間就在背景 mount，階段二淡入時已經是準備好的畫面，不會卡頓。
- 所有關閉面板的路徑（Escape、`closePanel`、`resetView`、切換場景、`travel()`）都同步把 `panelPhase` 重置回 `'shell'`。
- 全螢幕退出按鈕（回到工坊）本來就在頂部標題列、不隨全螢幕被隱藏，與模擬器自己畫的右下角面板（見 `turntable:3`）本來就不重疊，此需求未額外修改。
- 沒有 Claude Design 執行環境可實跑驗證；改以抽出 `<script>` 區塊、shim `DCLogic`/`React` 後在瀏覽器跑語法與方法呼叫檢查（class 解析成功、`CORNERS`/`AREAS`/`EXITS` 筆數正確、`paintPanelPhase()` 呼叫兩次不拋錯、opacity/animation 確實依 phase 切換），但無法涵蓋實際鏡頭轉場與 DOM 版面的視覺驗收，麻煩設計端或老師實際操作一次確認觀感。
